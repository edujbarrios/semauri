# Semauri 0.68.0 — Collection performance

Semauri v0.68.0 improves collection processing without changing the
language surface, type system, declared effects, or permissions.

## Performance improvements

- `distinct of`, `cardinality of`, `count distinct of` and `count unique of`
  use value fingerprints with collision-checked hash buckets instead of
  scanning all prior unique values. On inputs with many distinct values,
  the previous quadratic number of equality checks becomes expected
  near-linear work, plus the cost of hashing each value.
- List transformations stop eagerly cloning each input element into the
  iterator environment. `map every`, `filter every`, counting,
  quantifiers and partitioning reuse the owned input value after
  evaluation, reducing allocations for text and nested collection items.

## Semantics and verification

- Stable first-occurrence ordering, exact integer/decimal distinctions,
  float signed-zero equality, nested list equality and collision safety
  are preserved.
- Unit and integration tests cover duplicates, large unique lists,
  text transformation and partitioning.
- The performance workflow additionally runs paired before/after
  CLI benchmarks against the pull request base revision **on the same
  runner**. Measurements include process startup, parsing, checking
  and execution; use the linked CI run for measured figures rather
  than assuming universal speedups.
- No additional Rust dependencies or runtime capabilities.
- Binary distribution targets Linux, Windows and macOS on x86_64/ARM64,
  with release checksums.
