# Semauri v0.78.0 — Text composition and project directory entrypoints

Semauri introduces more natural text-processing expressions, and simplifies
running a complete project, while keeping the same static type checks and
explicit capabilities.

## New language expressions

```text
let message be "  Hello   ñ 🌍  ".
assert word count of message is equal to 3.
assert first word of message is equal to "Hello".
assert last word of message is equal to "🌍".
print normalize whitespace of message.
```

Output: `Hello ñ 🌍`.

- `first word of TEXT`, `last word of TEXT`
- `first line of TEXT`, `last line of TEXT`
- `word count of TEXT`, `line count of TEXT`
- `normalize whitespace of TEXT`

These are pure compositions of existing typed text and collection operations.
They preserve Unicode scalar values, don't introduce new permissions, and
evaluate the input once. Text must be statically typed as a string. Selection
from empty words/lines retains existing first/last runtime errors.
Whitespace normalization collapses Unicode whitespace (not Unicode NFC/case).

## Project runner

```sh
semauri init demo
semauri check demo
semauri run demo
# From within the project:
semauri run .
semauri .
```

Directory execution selects `main.suri` only; source imports and runtime
configuration resolution follow the actual entry path, and filesystem, AI,
configuration, and secure randomness continue to require their existing
explicit permissions. A directory with no `main.suri` is rejected.

## Quality and compatibility

A new runnable example, `examples/text_composition.suri`, and integration
tests cover type safety, Unicode behavior, formatter contextualization,
compile/optimizer/effect compatibility, project execution and permission
isolation. Existing syntax and CLI commands remain supported. No new Rust
dependencies are introduced.
