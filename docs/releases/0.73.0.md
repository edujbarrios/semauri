# Semauri 0.73.0 — Typed data, library namespaces and AI governance

This release consolidates the work from development PR #341 on top of v0.72.0
and adds runtime guards and machine-readable accounting for local AI workflows.

## Better foundations for AI programs

- **Structural records:** `record of ("name": "Ada", "age": 37)`
  with typed `field "name" of RECORD` access. Use explicit structural types in
  function parameters, nested records, and deterministic JSON serialization.
- **Homogeneous dictionaries:** `dictionary of ("label": "cat")`,
  `entry "label" of DICTIONARY`, explicit typed empty dictionaries,
  `has entry "label" in DICTIONARY`, `keys of DICTIONARY`,
  and lazy `entry "missing" of DICTIONARY with default "unknown"`.
  Typed lookups avoid missing-key crashes when a default is supplied.
- **Named imported libraries:** `import "library:math_kit" as math.`
  then `invoke math.square to 7`. Aliases prevent collisions between
  functions exported by different Semauri libraries.

These changes span the parser, type system, intermediate representations,
optimizer, formatter, effect checker and runtime, with source-located errors
and new Rust regression suites.

## Bounded AI prompts and usage telemetry

```text
bound ai prompts to 4 characters.
cap ai requests to 1.
memoize ai response cache.
let model be connect language model "local/test".
let first be prompt model with "hola".
let again be prompt model with "hola".
let metrics be report ai usage.
print metrics.
```

The report is deterministic JSON containing `requests`, `request_limit`,
`prompt_character_limit`, `cache_hits` and `cache_entries`. Prompts and
model identifiers are not included. Input bounds count Unicode scalars;
oversized prompts are rejected before requests or cache hits. Embeddings
now also obey the request budget and input bound.

These are **local runtime policies**, not provider-side token or monetary
budgets. Model execution remains limited to the existing `local/*`
backend without an added provider adapter. All model, network, inference
and output effects still require explicit `--allow` permissions.

## Compatibility and distribution

- No additional compiler dependencies or implicit capabilities.
- Existing unaliased imports remain compatible. Records and dictionaries
  are immutable; dynamically constructed schemas and native plugin ABI
  support are not included.
- The Jupyter integration remains native Rust; CI pins a supported Ubuntu
  runner and retries package retrieval to reduce runner-image instability.
- Package, lockfile, citation metadata, Jupyter language version and
  release notes advance together to **0.73.0**.
- The release workflow builds, smoke-tests and publishes six archives for
  Linux, macOS and Windows (x86_64 / ARM64) with `SHA256SUMS` only after
  all distribution jobs succeed.
