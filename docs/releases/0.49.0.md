# Semauri 0.49.0 — Faster compile-time evaluation

Semauri 0.49.0 is an optimization release. It does **not** change Semauri
syntax, static types, effects, security limits, error diagnostics or the
observable output of language programs.

## What changed

- **Lazy semantic explanations:** CLI `check`, `run`, and normal
  code-generation paths avoid expensive string formatting and list
  descriptions when no explanation was requested. `semauri explain FILE`
  and `semauri explain FILE --json` keep their full existing output.
- **Fewer copies:** fast borrowed/indexed symbol lookup, less cloning
  during resolution and preallocated list transformation buffers.
- **Cheaper lexical environments:** safe frame recycling and deterministic
  numeric symbol-ID hashing reduce repeated allocation in map/filter/count
  and function calls.
- **Regression tests:** ensure that skipping explanations does not
  affect semantic output, errors or explicit explanations.

## End-to-end benchmark: Semauri 0.48.0 versus 0.49.0 candidate

Measured on the same Linux x86_64 GitHub Actions runner (AMD EPYC 7763
64-Core Processor, Linux 6.8.0-1064-azure). Release builds, 3 warmup runs
and 50 timed processes per workload and implementation. Output bytes are
checked on every run. These are medians in milliseconds:

| Workload | Before | After | Speedup | CPython |
|---|---:|---:|---:|---:|
| hello | 1.513 | 1.515 | 1.00x | 15.532 |
| map_reduce | 27.386 | 7.769 | 3.53x | 17.105 |
| filter_count | 14.574 | 6.866 | 2.12x | 16.244 |
| sort | 7.381 | 3.229 | 2.29x | 15.998 |
| text | 20.224 | 8.387 | 2.41x | 16.845 |

Benchmark source and runner:
https://github.com/edujbarrios/semauri/actions/runs/40519737753

These are end-to-end timings; your CPU and load will yield different results.
The benchmark programs and Python references are in `benches/`.
To reproduce, build with `cargo build --release` and run
`bash scripts/bench.sh 50`.

## Explain and compatibility

```sh
semauri check examples/explain_walkthrough.suri
semauri explain examples/explain_walkthrough.suri
semauri explain examples/explain_walkthrough.suri --json
```

The explanation commands still preserve the established numbered trace
and ordered JSON array; the check command no longer builds that trace
unnecessarily. No changes to `MAX_RANGE_ELEMENTS` or to any existing
capability boundaries are made.

## Distribution
