# Semauri 0.75.1 — Secure random generation and contextual variable names

This maintenance release consolidates the new secure-password functionality from [v0.75.0](0.75.0.md) and corrects contextual parsing so common names such as `password` remain legal variables.

## Generate a password

```text
let password be password of 20 characters.
print password.
```

```sh
semauri run examples/secure_password.suri --allow secure_random --allow console_write
```

The default alphabet contains lowercase and uppercase letters, digits and common punctuation. For a custom alphabet:

```text
let token be secure random string of 32 characters from "abcdef0123456789".
let dice be draw random integer from 1 to 6.
let letter be pick random character from "ABCD".
```

### Fixed compatibility

Random-operation verbs `password`, `secure`, `draw` and `pick` are recognized contextually, not as universally reserved identifiers. You can now declare and reference variables with those names while still invoking the corresponding secure random operation. Function names such as `pick` remain supported.

### Security and bounds

- Random values are sampled from the operating system CSPRNG: `/dev/urandom` (Linux/macOS) or `BCryptGenRandom` (Windows).
- Rejection sampling avoids modulo bias for strings, Unicode character choices and inclusive signed 64-bit integer ranges.
- Strings must have 1–4096 characters; custom alphabets must contain 1–4096 distinct Unicode scalar values.
- All random operations require `--allow secure_random`; `print` additionally requires `--allow console_write`. Do not print production secrets into logs.
- No new Rust dependencies or changes to previous capability requirements.
