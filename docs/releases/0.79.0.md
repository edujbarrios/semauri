# Semauri v0.79.0 — Exact whole-word and whole-line matching

Semauri adds two natural, strictly typed text predicates for cases where
substring matching is too broad.

## New expressions

```text
let message be "Ada Lovelace\nGrace Hopper\nAda".
assert message has word "Ada".
assert message does not have word "Lov".
assert message has line "Grace Hopper".
assert message does not have line "Hopper".
print "Whole-text matching OK".
```

Output: `Whole-text matching OK`.

- `TEXT has word VALUE`: search Unicode whitespace-delimited words.
- `TEXT has line VALUE`: search exact LF/CRLF-delimited lines.
- `TEXT does not have word VALUE` and `TEXT does not have line VALUE`: boolean negation.

The existing `contains` remains a substring/membership operator; it
is **not** changed. Whole-word matching is punctuation-sensitive, not
linguistic tokenization: `"hello!" has word "hello"` is false.
Matching is case-sensitive, Unicode-aware, and does not perform regex,
normalization, or locale-specific matching. Empty text contains no words or
lines. Lines preserve interior blanks and omit the final empty field.

## Safety, tooling and compatibility

The parser lowers these forms to existing typed `words of` /
`lines of` plus `contains` and optional boolean `not`.
Both inputs are evaluated once, type errors remain compile-time errors, and
the runtime/effects/optimizer need no new operations. The formatter
canonicalizes only complete predicates, preserving variable names.
Existing programs and CLI behavior are unchanged.

The release adds a runnable example, integration tests, and language-guide
documentation. No new Rust dependencies or permissions are introduced.
