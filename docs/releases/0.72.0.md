# Semauri 0.72.0 — External libraries and Rust-only tooling

Semauri v0.72.0 introduces **explicit, versioned, locally installed complementary
libraries** so authors can share and reuse `.suri` functions across projects.
It also adds natural-language syntax enhancements and replaces the project's
remaining Python-based internal tooling and Jupyter adapter with Rust.

## Create a Semauri-compatible library

A library consists of ordinary Semauri source and a small descriptor:

```text
# libraries/math_boost/lib.suri
define function triple taking n as number to (n times 3).
```

```json
{
  "schema": 1,
  "name": "math_boost",
  "version": "1.0.0",
  "entry": "lib.suri"
}
```

Save the descriptor as `libraries/math_boost/.semauri-library.json`,
and declare it in the application's `.semauri-libraries.json`:

```json
{
  "schema": 1,
  "libraries": [
    {"name": "math_boost", "version": "1.0.0", "path": "libraries/math_boost"}
  ]
}
```

The application can import and call it using checked Semauri syntax:

```text
import "library:math_boost".
print invoke triple to 7.
```

```sh
semauri libraries app
semauri check app/main.suri
semauri run --allow console_write app/main.suri
```

The output is `21`. Use `semauri init app` to create a project with an
empty library catalog. Libraries can be placed in an explicit sibling folder
outside the project; nested imports remain confined to each library's
canonical directory. Catalogs pin a `MAJOR.MINOR.PATCH` version and check
library identity on every load, with `S417` for declaration errors.

**Security:** Semauri still statically checks third-party sources, preserves
source-file diagnostics, and enforces `--allow` capabilities when running
imported effects. It rejects unlisted dependencies, cycles, symlink escapes
and unrestricted external imports. This first version handles **offline,
locally installed `.suri` source libraries** only: it is not a remote package
registry, automatic downloader, cryptographic lockfile or native Rust/C ABI.

the [full guide](../external-libraries.md), and the

## New language expressions

- `x is not greater than y`, `x is no greater than y`: checked `x ≤ y`.
- `x is not less than y`, `x is no less than y`: checked `x ≥ y`.
- `x is not greater than or equal to y` and
  `x is not less than or equal to y`: strict complements `x < y` / `x > y`.
- `range from 1 through 5` is an inclusive alias for `range from 1 to 5`.
- Optional trailing commas in lists (`a list of 1, 2,.`) and
  function calls (`invoke combine to (1, 2,)`).

These additions preserve precise numeric typing, existing diagnostics and
runtime capabilities. They are tested in
`tests/natural_language_ergonomics.rs`.

## Rust-only internal tools and Jupyter support

- Replace five Python benchmarking/report scripts with the
  `semauri_bench` Rust CLI and update the performance CI.
- Replace the Python Jupyter kernel adapter with a native Rust ZeroMQ kernel,
  authenticated messaging, permission-aware isolated cell execution and
  integration protocol tests.
- Remove repository-owned Python source files; guard against their
  reintroduction in Rust regression tests.
- Accept an optional leading UTF-8 BOM on `.suri` source files and imports.
- Keep project creation, diagnostics, build, test, and verification workflows
  compatible with existing Semauri programs.

JupyterLab itself remains a separate application and may have Python
dependencies; Semauri's own kernel integration is written in Rust.

## Release, compatibility and downloads

The Semauri compiler package, CLI, Cargo lockfile, citation metadata, and
native Jupyter language identifier have been updated to **0.72.0**. No
additional root compiler crate dependencies or implicit runtime permissions
are introduced.

The release workflow builds and smoke-tests native packages for
**Linux (x86_64, ARM64)**, **macOS (Intel, Apple Silicon)**, and
**Windows (x86_64, ARM64)** and publishes a `SHA256SUMS` integrity file
when all package jobs complete.

See [GitHub Releases](https://github.com/edujbarrios/semauri/releases)
for release downloads, and read the
[language guide](../language-guide.md) for full syntax and capabilities.
