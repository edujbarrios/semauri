# Semauri 0.44.0

Semauri 0.44.0 makes the assertion-test workflow safer, more scriptable,
and faster to use during iterative development. This release follows
0.43.0's project-wide verification and formatting tools.

## Bounded test discovery

`semauri test PATH` still recursively discovers `.suri` assertion tests,
but it now caps discovery at **256 files** and **32 directory levels**.
It skips symlinks, `.config.suri`, and generated folders such as
`target`, `.git`, `node_modules`, `.venv`, and `.semauri-cache`.
Exceeding a bound fails with exit code 64 **before running tests**.

The test runner still rejects non-console effects and generated build
artifacts, and printing from tests requires `--allow-console`.

## JSON reports for CI and editors

```sh
semauri test tests --json
semauri test tests --allow-console --json
```

JSON mode emits an object with `ok`, `status`, `passed`, `failed`
and `tests`. Each test has its source `path` and `ok` result;
failures additionally contain an `error` string with the diagnostic.
Invalid paths and command arguments return a structured `error`
message with an empty test array when JSON output is enabled.

Exit statuses remain 0 for success, 1 for failed assertions and
64 for invalid CLI usage or test discovery.

## Run only relevant tests

```sh
semauri test tests --filter arithmetic
semauri test tests --filter module/math --json
```

`--filter TEXT` selects test files whose **relative path** contains
the supplied substring. Matching is case-sensitive and path separators
are normalized to forward slashes. An unmatched filter returns exit
code 64 rather than silently reporting success. The selector can be
combined with JSON output and explicit console permissions.

## Compatibility

Existing `.suri` syntax, compilation, optimizer, runtimes, backends,
project verification, text test reports and effects policies are
unchanged. These changes affect developer tooling, not language grammar.
Programs remain sandboxed by the same explicit permission checks.

The release is built for Linux, macOS and Windows on x86_64 and ARM64.
Verify official archives with the `SHA256SUMS` file attached to
the GitHub Release.
