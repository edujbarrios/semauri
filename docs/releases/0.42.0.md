# Semauri 0.42.0

Semauri 0.42.0 introduces practical multi-file development. Programs can
import reusable typed functions from local `.suri` files, and a new project
initializer creates a ready-to-run application and test suite.

## Build real multi-file programs

Create a reusable library:

```text
# lib/math.suri
define function square taking n as number to (n times n).
```

Use it in an entry point:

```text
# main.suri
import "lib/math.suri".
assert invoke square to 7 is equal to 49.
print invoke square to 7.
```

Imports are resolved at **compile time** before normal parsing and type
checking. Multiple files are combined into one checked symbol namespace.
Each canonical file is imported at most once. Imported side effects remain
visible to `effects` inspection and require the same `--allow` grants as
effects written in the entry file.

## Create a new project

```sh
semauri init my-project
cd my-project
semauri check main.suri
semauri run --allow console_write main.suri
semauri test tests --allow-console
```

The initializer creates:

- `main.suri` — a checked, executable example
- `lib/math.suri` — a reusable, statically typed function
- `tests/math.suri` — an executable assertion test
- `.semauri-root` — the import safety boundary
- `README.md` — concise command instructions

Initialization only creates a **new** directory; it will not overwrite an
existing project or run its generated code automatically.

## Import safety

- Each import uses a quoted relative `.suri` path.
- Nested imports resolve relative to the file that declares the import.
- The nearest ancestor `.semauri-root` regular file marks the project
  boundary, enabling tests to import from a shared library folder.
- Without a marker, imports are restricted to the entry file's directory.
- Canonicalization rejects symlink and traversal escapes.
- Circular imports, imports after executable statements, missing/invalid
  paths, and imports outside the project root produce `S416`.
- The loader limits source graphs to 64 files, 32 import levels, and 4 MiB
  aggregate UTF-8 text.

The file-based CLI commands `check`, `build`, `run`, `test`,
`hir`, `effects`, `plan` and other inspection commands resolve imports.
The formatter preserves import strings and edits only the specified file.
Where available, CLI diagnostics report the **original file and line** even
after import expansion.

## Compatibility and limitations

Existing single-file programs behave as before. In-memory
`Compiler::parse` and `Compiler::hir` still operate on source text
and do not resolve file paths. Imported declarations currently share one
namespace; namespacing, package management, and separate compilation are
future milestones. Module source reading happens at compile time, not as
a runtime filesystem effect.
