# Semauri 0.74.0 — Core expressions, bounded agents and structured JSON

Release date: 2026-11-11. This release includes **all development pull requests #342, #343 and #344**, merged into `main` before publication.

## Improvements to Semauri the programming language

- **Exclusive-or:** write `a xor b` with strict Boolean typing, predictable precedence between `and` and `or`, optimizer folding and contextual syntax (an identifier named `xor` still works).
- **Dynamic Boolean expressions:** `not`, `xor`, `is equal to` and `is not equal to` can operate on runtime values through typed, pure SSA `core` operations; assertions and dataflow remain inspectable.
- **Dynamic numeric expressions:** unary `minus`, subtraction and strict/inclusive numeric comparison support values read at runtime. Integer subtraction and ordering remain exact beyond 2^53; signed overflow raises source-located S470 or S358 rather than silently wrapping.
- The existing formatter, static type checker, optimizer, CLI capability gates, VS Code syntax highlighting and Jupyter completions are updated, with new tests and examples.

## Safer AI orchestration and data processing

- Enforce per-agent turn limits, including successful cache hits; maintain distinct system contexts for cache isolation.
- Bound cached responses with `constrain ai cache to N entries.` (FIFO eviction), `reset ai response cache.`, and `restrict ai outputs to N characters.`
- Validate text with `validate ai json DATA against schema CONTRACT` and `normalize ai json DATA against schema CONTRACT`. The strict, bounded subset supports primitive types, object properties, required fields, nested arrays, string enumerations, and size limits. Unknown schema keywords and duplicate keys fail closed.
- Permit the nominal `ai.response` type as a string input while keeping model, tool and agent identity types distinct. Extend `report ai usage` metrics without exposing prompts.

## Compatibility, testing and limitations

- No new core Rust dependencies. Existing 0.73.0 syntax and explicit `--allow` permissions are preserved.
- Runtime-dependent `and`/`or` and conditional branches remain intentionally unsupported until a proper control-flow graph is introduced. Other runtime arithmetic is not yet lowered.
- `local/*` AI models remain deterministic simulators. This release does **not** introduce a real third-party model provider or full JSON Schema support.
- CI validates Rust tests, native Jupyter, compiler performance, Clippy and six native distribution targets (Linux/macOS/Windows, x86_64 and ARM64). Release files include SHA-256 checksums.
