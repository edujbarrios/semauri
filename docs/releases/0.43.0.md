# Semauri 0.43.0

Semauri 0.43.0 adds project-wide quality checks and recursive formatting,
building on 0.42.0's multi-file imports and `semauri init`. These tools
make it much easier to maintain a Semauri project and run the same quality
gate in local development and continuous integration.

## Verify a complete project

```sh
semauri init demo
semauri verify demo
semauri verify demo --json
```

`semauri verify PROJECT` requires a `.semauri-root`, `main.suri`,
and a `tests/` directory. It:

- Checks canonical formatting across every `.suri` source file.
- Statically type-checks library-only modules, and fully checks the entry
  point and executable assertion tests with their imports.
- Reports the entry program's required effects.
- Runs tests using the existing restricted assertion test runner.

The application's `main.suri` is **never executed during verification**.
Tests cannot execute filesystem, network or other non-console effects.
Test output needs explicit authorization with `--allow-console`.

The `--json` option provides stable machine-readable fields for success,
status, project path, source count, effects, test output and issues.
Status is 0 for success, 1 for verification failures and 64 for invalid
project layout or CLI usage.

The verifier skips symlinks, build caches and `.config.suri`, with limits
of 256 source files and 4 MiB of total `.suri` source text.

## Format every source file

```sh
semauri fmt demo --check
semauri fmt demo --write
semauri verify demo
```

Directory formatting is available only with `--check` or `--write`;
single-file formatting behaves as before. A directory `--check` reports
all noncanonical files and returns status 1 if changes are needed.
`--write` preflights every file first so invalid lexer input anywhere
cannot cause a partial formatting pass, then writes changed files.

Formatting performs no program execution and requires no new effect grants.

## Compatibility and future work

Existing Semauri sources, local imports, capability policies, and
runtime/backends remain supported. The new project gate does not replace
deployment or full end-to-end integration testing. Module namespaces,
package distribution, dynamic network I/O, and richer host APIs remain
future milestones.

The release includes Rust regression tests, updated documentation,
and platform archives for Linux, macOS, and Windows on x86_64 and ARM64.
Verify downloaded archives with `SHA256SUMS` from the release assets.
