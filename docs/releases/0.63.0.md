# Semauri 0.63.0 — Natural numeric predicates and boundaries

Semauri keeps its statically typed semantics while gaining more expressive
English-like numeric conditions. This release builds on v0.62.0.

### Numeric predicates

- `NUMBER is zero` / `is not zero` works with integers and decimals, including signed zero.
- `NUMBER is positive` / `is not positive` and `is negative` / `is not negative` use Semauri's checked numeric `sign of` path.
- `INTEGER is even` / `is not even` and `is odd` / `is not odd` share the existing checked parity path (invalid non-integral values still produce `S426`).

### Clear numeric comparisons

- `VALUE is at least LIMIT` — inclusive numeric greater-than-or-equal.
- `VALUE is at most LIMIT` — inclusive numeric less-than-or-equal.
- `VALUE is above LIMIT` and `VALUE is below LIMIT` — strict numeric comparisons.

All new expressions reuse existing checked AST/HIR/optimizer/runtime semantics;
no implicit conversions, additional dependencies, or effect permissions.

### Tooling and examples

Includes regression tests, documentation, a runnable example, updated VS Code
syntax highlighting, and Jupyter completion/help updates. See
`examples/natural_numeric_predicates.suri`,
`examples/natural_bounds.suri`, and `docs/language-guide.md`.
