# Semauri v0.25.0 — Pure Typed Functions

Semauri 0.25.0 adds its first **reusable user-defined functions** to the Rust-implemented, statically typed compiler. Functions integrate with the existing typed `map every` and `filter every` syntax to make data transformations more readable without compromising determinism or capability safety.

## Define and call a function

```sema
define function square taking n as number to (n times n).
define function large taking n as number to (n is greater than 5).
let numbers be range from 1 to 4.
let squares be map every n in numbers to (invoke square to n).
let selected be filter every n in squares if (invoke large to n).
print squares.
print selected.
```

Expected output:

```text
[1, 4, 9, 16]
[9, 16]
```

Each function declares exactly one input type: `number`, `string`, `boolean`, `color` or recursively nested `list of TYPE`. The compiler infers the result type from the pure expression body and checks every invocation. Parameters are immutable, may shadow enclosing values, and are scoped to individual calls.

## Count matching elements directly

```sema
let observations be range from 1 to 8.
let even_count be count every n in observations if ((n modulo 2) is equal to 0).
assert even_count is equal to 4.
```

`count every` is a pure typed predicate reduction that returns an exact integer `number` matching count without materializing a filtered list. It preserves source lists and lexical iterator scope; it is equivalent in result to `length of (filter every ...)` for concrete values. Non-list input raises S365, nonboolean predicates S366, and a hypothetical overflowing count S373. An empty typed list returns zero; `count` remains a valid identifier outside `count every`. See [predicate counting semantics](../36_COUNT_EVERY.md) and [PR #173](https://github.com/edujbarrios/semauri/pull/173).

## Lexical scoping and safe composition

Functions may reference earlier immutable top-level symbols and call other previously declared functions. The optimizer and effect analyzer traverse function calls and their argument/body expressions; caller and parameter environments remain separated. Definition names are unique; declaring a function must precede use, and recursive/forward calls are deliberately unsupported.

The new contextual keyword is `invoke`, not `apply`: the latter already participates in the ML semantic operation `apply lora`. Existing ML domain syntax is preserved.

## Diagnostics and limitations

- `S246`/`S247`: malformed declaration or invocation syntax.
- `S369`/`S370`: unknown function or argument type mismatch.
- `S371`/`S372`: duplicate definition, impure body or unsupported declaration scope.

This version **does not** support multi-parameter functions, recursion, first-class callable values, effectful function bodies, streaming datasets, or execution of ML model training. Runtime-only values are not accepted by these compile-time-known core expression functions.
